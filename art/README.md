# 灵火破晓 · 美术资产管线规范

把游戏里的程序化模型（脚本拼装的白模）升级成带 PBR 贴图、LOD、蒙皮的正式美术资产。
流程按游戏行业惯例设计：**白模驱动、阶段化、版本化、有人工闸门、自动 QA、引擎只认清单**。

```
游戏白模 ──▶ 00 白模 ──▶ 01 概念设计 ──▶ 02 高模 ──▶ 03 游戏化 ──▶ 04 自动QA ──▶ 05 审核 ──▶ 06 发布
(?debug 导出)  四视图+相机     GPT Image 2.5     Hunyuan3D 2.1    Blender 无头      GLB+度量     审核大图     public/assets
               参数            重绘+配准 ◆闸门    (本地 ComfyUI)    减面/UV/烘焙/       校验                ◆闸门   + manifest.json
                                                                   蒙皮/LOD/导出
```

| 环节 | 工具 | 运行位置 |
|---|---|---|
| 白模导出 | `src/dev/artExport.ts`（游戏 `?debug`） | 本地浏览器 |
| 概念设计 | OpenAI `gpt-image-2.5-sunburst`（`/v1/images/edits`，白模作参考图） | 云端 API |
| 高模 | Hunyuan3D 2.1（ComfyUI 原生节点，`hunyuan_3d_v2.1.safetensors`） | 本地 GPU |
| 游戏化 / 审核图 | Blender 5.2 无头模式（Cycles OptiX 烘焙、EEVEE 渲染） | 本地 GPU |
| 校验 / 发布 | Python 3.11（Pillow、numpy） | 本地 |

---

## 1. 为什么以白模为准

程序化模型定义了**玩法尺度**：身高、头部判定球、关节位置、武器挂点、碰撞胶囊。美术资产必须服从这些尺度，
而不是反过来。所以每个资产都从白模出发：

- 概念图是白模四视图的**重绘（paintover）**，比例、姿势、站位与白模一致；
- 高模按白模相机**对齐**（剪影 IoU 搜索），脚底落在原点；
- 骨骼直接用白模关节（同名、同位置），运行时 SkinnedMesh 绑在游戏关节上，**程序动画代码一行不改**。

## 3. 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 资产 ID | `SK_`（骨骼网格）/ `SM_`（静态网格）+ `<类>_<名>`，帕斯卡命名 | `SK_Enemy_Grunt`、`SM_Weapon_Revolver` |
| 网格 / LOD | `<资产ID>_LOD<n>` | `SK_Enemy_Grunt_LOD0` |
| 材质 | `M_<类>_<名>`，一个资产一个材质 | `M_Enemy_Grunt` |
| 贴图 | `T_<类>_<名>_<后缀>`：`BC` 基础色（sRGB）、`N` 法线（线性、OpenGL/glTF 约定 Y+）、`ORM`（R=AO G=粗糙度 B=金属度，线性）、`E` 自发光 | `T_Enemy_Grunt_ORM` |
| 骨骼 | 与游戏关节同名 | `hips` `torso` `head` `armL` `elbowL` `handL` … |
| 阶段文件 | `<前缀>_<资产ID>_v<三位版本>`：BO 白模 / CN 概念 / HP 高模 | `CN_SK_Enemy_Grunt_v001_front.png` |

不符合规范的资产 ID 在登记时就会被拒绝；材质、贴图、LOD 命名由自动 QA 检查。

## 4. 坐标与单位

- 单位：米。游戏 / glTF：**Y 向上，角色朝 +Z，轴心在脚底中心**。Blender 里对应 Z 向上、朝 −Y（导入导出自动换算）。
- 四个标准视图（白模渲染、概念、投影共用）：front 看脸、left 角色面朝画面左、back、right 角色面朝画面右。
- 骨骼网格的绑定姿势是 **A-pose**：上臂外展 `BIND_ARM_SPREAD = 0.45` 弧度（`src/assets/HumanoidBind.ts`），
  其余关节零旋转。导出白模和运行时绑定都调用同一个 `applyBindPose`。

## 6. 各阶段与命令

所有命令在项目根目录执行：`python art/pipeline/assetctl.py <命令> <资产ID>`。
每个阶段只读上游的**当前版本**；每次运行产出新版本，**从不覆盖**；上游换版本时下游的当前版本自动作废。

| # | 命令 | 做什么 | 产出 / 记录 |
|---|---|---|---|
| 0 | 登记 | 在 `registry.toml` 加一节：规格档、白模来源、材质常量、英文设定 brief、绑定规格（`garment`，可选） | — |
| 00 | `serve` + 游戏控制台导出 | 开接收端；游戏 `?debug` 控制台执行 `(await import('/src/dev/artExport.ts')).exportEnemyBlockout('<敌人id>', '<资产ID>')`。挂件（武器）不进四视图 | 白模 GLB、关节说明（绑定位置 / 局部位置 / 绑定旋转 / 部件中心 / 头部锚点 / 部件角色）、四视图与相机参数。几何不变时原地修订说明文件，不作废下游 |
| 01 | `concept` | 白模四视图作参考图，GPT Image 2.5 重绘成设定四视图；自动切分人物并**配准**回白模相机（缩放 + 平移，最大化剪影 IoU） | 原图、配准后四视图、白模对照图（含 IoU）、提示词全文、用量、请求号。**◆闸门**：`approve <ID> concept --by <人>` |
| 01b | `matid`（可选） | 拿审核通过的概念图再出一张同构图的材质分区图，用**红蓝编码**（红 = 金属、蓝 = 非金属；比黑白编码稳，原本就是白色的骨头 / 布不会被误留成「金属白」），解码成灰度遮罩，逐视图配准到概念剪影上。概念里容易误判的材质（发亮的甲壳、上了釉的石头、金色但不是金属的纹样）在登记表写 `matid_hint`，原文附在提示词后面 | 遮罩四视图、对照图（红 = 金属）、各视图金属占比与编码纯度（< 85% 提示不可靠）。游戏化阶段用它烘出金属度并推导分区粗糙度；新遮罩只作废游戏化及之后，不影响高模 |
| 01c | `emid`（可选） | 发光分区：从概念图出同构图的红蓝编码自发光遮罩（红 = 会发光的细节：雕刻纹路、符文刻槽、散热缝、能量导管）；`emissive_hint` 写明哪些细节发光 | 遮罩四视图、对照图（青 = 发光）、各视图发光占比。游戏化阶段同一套投影烘成 `T_*_E`（锐化成近似二值），接到材质的自发光上；运行时按实例着色 |

| 03 | `build` | Blender：清理 → 体素重建拓扑（水密流形）→ 朝向 / 缩放 / 平移对齐 → 减面 LOD0 → **自动展 UV，两种方案择优**（A：智能展开直接打包；B：智能展开的小岛并入共享边界最长的邻块 → 图块边界平滑 → 真实几何上最小拉伸展开 → 有翻折的块逐级细化重做。按面积加权的平均纹素密度取高者，B 有翻折即淘汰。Hunyuan 网格法线杂乱，碎岛严重的资产（弓手、蛮兵、Boss）B 多出一成以上清晰度；本来就较紧凑的资产 A 更好，实测两者互有胜负，所以每次都比）→ 四视图投影着色（法线权重 × 射线遮挡 × alpha，盲区网格扩散补色）→ 烘焙 BC / N / AO → 打包 ORM → LOD1..n → **骨骼适配网格**（测量高模前臂的实际外展角，按实测角度摆手臂骨，角度写进清单）→ bone heat 自动权重（某级 LOD 大面积求解失败时，从求解成功的 LOD 代理插值传递权重；零星失败顶点用平滑邻近权重）→ **衣摆权重平均化**（离腿骨明显远于腿部的衣摆顶点，部分权重给髋骨、其余左右平均，防止被双腿撕开；登记 `garment = "long_robe"` 的长袍角色从脚踝到髋部整体平均，脚只保留 25% 腿部运动）→ **刚性头部**（白模头部部件包围盒内的顶点 100% 绑头骨，防止宽帽檐、兜帽被手臂骨拉歪）→ **手臂胶囊约束**（离「肩→肘→腕→手尖」折线超过登记的 `arm_radius` 的顶点，手臂骨权重按距离衰减、转给躯干，髋部以下转给髋骨，防止斗篷、躯干侧面被手臂骨带走）→ ≤4 影响、归一化 → 导出。非人形资产走部件骨架，见 6.4 | `.blend` 工程、贴图、GLB、度量 JSON |
| 04 | `validate` | 包级 + DCC 级自动 QA（见第 7 节） | 校验报告；有错误则阻塞 |
| 05 | `review` | 渲染审核大图：成品四视图 + 3/4、各级 LOD 布线、姿势测试（与游戏完全同一套关节语义：待机 / 行走 / 攻击）、贴图；**自动形变检测**：姿势下每条边相对静止长度的拉伸，p99 > 1.8 或过度拉伸边 > 1% 时标红提示重点检查 | 审核图。**◆闸门**：`approve <ID> review --by <人>` |
| 06 | `publish` | 拷到 `public/assets`，更新 `manifest.json`（Draco 解码器由 Vite 从 three 包自动打包） | 清单条目（URL、绑定目标、LOD 距离、包围盒、版本血缘、校验和、许可） |

快捷方式：`run <ID> --from highpoly --to review` 连续跑多个阶段（遇到闸门停下）；`batch <阶段|run> --class enemy_attachment`（或 `--assets A B …` / `--all`）对多个资产执行，单个失败不中断，最后汇总。`status <ID>` 看进度，`list` 看全部资产。
`concept-register <ID>` 在不重新调用接口的情况下对当前概念重新配准。概念不满意：`reject … --note <原因>`，再 `concept <ID> --note "<修改要求>"` 出新版本。

## 6.1 静态挂件（SM_，武器 / 盾 / 法器）

- **挂点**：挂件是 buildModel 里命名过的子节点（`blade.name = 'scimitar'`，相当于引擎里的 socket 名），登记表用
  `blockout = { source = "enemy", id = "grunt", attachment = "scimitar" }` 绑定。名字是代码和资产之间的显式契约，不依赖子节点顺序。
- **白模**：`exportEnemyAttachment(enemyId, attachment, assetId)` 在挂点的局部空间导出（原点 = 挂点），角色记为
  body / glow（发光提示件）/ glowfx（加法特效件，不进四视图）。
- **展示姿态**：渲染四视图前自动旋转成「最长轴竖直、最薄方向朝正面相机」，正面图就是信息量最大的侧影（刀身平面、弩的俯视、火枪侧面），
  Hunyuan 用它重建；旋转矩阵记在白模相机参数里，游戏化导出前转回挂点局部空间，审核图按展示姿态渲染。
- **对齐**：挂件不做脚底落地，原点保持在挂点。单视图重建对深度轴（展示姿态里朝相机的方向）只能猜，校验对它只给警告，两个主轴严格 ±15%。
- **运行时**：`StaticAttachment.attachStaticPart` 隐藏挂点下的脚本实体部件、保留发光提示件，把美术 LOD 挂到挂点下，挂点的程序动画（瞄准俯仰、抬举）照常生效。

## 6.2 材质与渲染

- 有材质分区时：金属区金属度 `metal_value`（默认 0.75）、粗糙度 `metal_roughness`（默认 0.4）；非金属区金属度 0、粗糙度 `roughness`；边界平滑过渡。
  手绘固有色里已经画了明暗，金属度不宜拉满。没有材质分区时退回 `roughness` / `metallic` 两个常量。
- 场景本身没有环境贴图，美术材质单独挂一张中性 RoomEnvironment 的 PMREM（`src/assets/ArtEnvironment.ts`，强度 0.6，与审核图的 Blender 世界光对齐），
  金属有光泽，又不改变场景里其他程序化材质的观感。

## 6.3 QA 豁免与并发

- 有意的设计偏差（比如把白模的两段式刀身改成一整片弯刀，刀身变宽）在登记表写 `qa_waivers = { "<检查项名>" = "<理由>" }`：
  校验报告里记为「◇ 已豁免」并留档理由，不阻塞流程；不要为此放宽全局阈值。
- 多个管线进程可能同时更新同一个 `asset.json`（比如材质分区和游戏化批次并行），状态写入有文件锁，锁内先重读磁盘最新状态再修改。

## 6.4 通用部件骨架（非人形敌人 / Boss，`rig = "parts"`）

- **骨骼 = 程序化模型的节点层级**：buildModel 里每个非网格节点就是一根骨骼，名字是从模型根出发的子节点索引路径
  （`j_r`、`j_0`、`j_2_1`……，`src/assets/PartsRig.ts` 的 `jointPaths`，导出器和运行时共用这一个函数）。不需要为每种怪手写骨架，
  游戏代码原有的程序动画（腿的摆动、灯身摇晃、Boss 的招式动作）直接驱动美术网格。
- **白模**：`exportEnemyParts('<敌人id>', '<资产ID>', { sockets: [...], rigFields: [...] })`。`sockets` 是另做静态资产的命名挂点；
  `rigFields` 是不进身体资产、运行时保持程序化的 rig 字段（独立运动的环绕浮石、半透明冰翼、带熔火发光的大剑），对应登记表 `blockout_exclude`。
  说明文件记每个关节的绑定位置 / 局部位置 / 绑定旋转 / 缩放，以及保留子树（keep）。
- **概念**：用生物版版式（`LAYOUT_CREATURE`），要求每条腿、翅、流苏、浮件保持白模的角度和长度，分开的部件保持分开。
- **分段**：每个白模实体部件是一个影响体积（OBB）。每个面按中心离哪个关节的体积最近归到该部件，再做清理：
  标签平滑（多数边邻面属于另一部件就改过去，消掉锯齿边界），小碎块（< 该部件面数 5%）并回周边部件。
  归属记在面属性 `part` 里，封口面继承相邻外表面的部件；蒙皮阶段直接读它（封口面的中心常离对侧部件更近，重新判定会留下长条）。
- **刚体模式**（`rig_rigid = true`，石像、甲壳、板甲、灯笼等硬表面角色）：所有部件交界都切开、封口，每个部件 100% 跟随自己的骨骼。
  关节转动时露出部件之间的缝（封口取边缘固有色的亮度中位色，整块一色），任何招式下拉伸为零。巨像、督军、爆骸虫、飞灯用它。
- **过渡模式**（默认，有机角色）：父子部件之间、以及共同父关节没有实体部件的兄弟部件之间（纯枢轴下的躯干↔胯 = 腰）平滑过渡，
  `w = exp(-(D - Dmin) / σ)` 取前 4 归一化，`rig_sigma`（相对资产尺寸，默认 0.015）是过渡带宽度；其余部件交界切开封口
  （垂在腰侧的前臂和躯干之间隔着肘和肩，不切开的话举臂时会把躯干拉出长条）。主母用它。
  转角极大的关节可以单独设为刚性：`rig_rigid_joints = ["armL", "armR"]`（rig 字段名）——该关节与父、兄弟关节的交界也切开，整段绕关节转，
  和子关节（肘以下）照常过渡。线性混合蒙皮在 150° 以上的转角必然拉长过渡带，调 `rig_sigma` 只是挪地方；切口藏在护肩一类的部件下面。
- **对齐**：不做脚底落地（飞行怪、Boss 的原点不在脚底），校验改为「竖直中心与白模一致」。
- **审核姿势**：登记了 ROM（`[assets.<ID>.rom]`，`{姿势名 = {rig 字段 = [x, y, z]}}`，取自招式代码的极限角度）时按它摆姿势、做形变检测，
  这是游戏真正会摆出的姿势；字段名经白模说明里的 `fields`（rig 字段 → 关节路径）换成关节。随机扰动（a = ±0.35、b = ±0.6 rad）只是没有 ROM 时的退路：
  它既测不到真实招式的极限（巨像砸地时双臂举到 −2.7 rad），又会测出游戏里不会出现的姿势。Boss 必须登记 ROM；招式代码改了幅度要同步。
  审核数据里的 `stretch_pairs` 列出过度拉伸最多的骨骼对，直接说明问题出在哪个关节。
- **运行时**：清单记骨架指纹（关节路径 + 静止局部位置）；`attachPartsBody` 逐一核对，模型代码改了对不上就放弃绑定、保留程序化模型，绝不绑错。
  绑定姿势取构建完成时的姿势，所以必须在任何动画运行之前调用（`EnemyArt.attachEnemyArt` 负责时机）。
  保留的小发光件（眼睛）和人形敌人一样吸附到美术网格表面并缩到 60%；大的光团（弱点核心、爆囊）、加法光环不动。
- **补说明字段**：导出器加了新字段（如 `fields`）时，先 `exportEnemyParts(..., { dryRun: true })` 拿 GLB 校验和，与 `asset.json` 里当前白模一致再正式导出，
  接收端才会原地修订说明文件；GLB 只要有一个字节不同就会开新版本，概念和高模全部作废。

## 6.5 第一人称武器（`SK_Weapon_*`，同一资产也用于掉落模型）

- **骨架**：通用部件骨架 + 刚体模式（`rig = "parts"`、`rig_rigid = true`）。弹匣、转轮、枪管组、泵动护木是骨骼，由 Viewmodel 原有的换弹 / 转轮 / 泵动动画驱动。
- **保留程序化**（`WeaponModels.PROCEDURAL_PARTS`，按节点名）：开镜视线要穿过的中空瞄具（步枪红点、连发步枪筒式瞄具）、按上弦状态显隐的弩箭、按上弦程度拉伸的弓弦。
  狙击枪开镜时第一人称模型整体隐藏、改用瞄准镜画面，所以它的瞄准镜做进美术资产。
- **白模**：`exportWeaponParts('<武器 id>', '<资产ID>')`。用基础稀有度、无元素导出；稀有度条、元素能量槽按实例变色，记为特效件（不进四视图、不烘进贴图）。
- **展示姿态**：`presentation = true`，枪管竖直、侧面朝相机出概念和高模（道具版式提示词），构建时在绑骨之前转回枪的局部空间；校验走分轴尺寸检查。
  高模用多视图（`highpoly_mode = "multiview"`），枪身宽度由侧视图约束。
- **发光**：程序化枪上的发光平板贴到美术枪上像贴纸（放不平、盖住纹饰），所以每把枪都做发光分区（`emid`）。运行时实例材质的自发光 =
  元素色（无元素时稀有度色）× 稀有度强度（0.5–2.0），第一人称按原能量槽的节奏脉动；程序化发光平板隐藏。没有发光遮罩的资产退回「把发光平板沿板面法线贴到美术表面」。
- **运行时**（`src/assets/RigidParts.ts`）：刚体资产不需要蒙皮——按骨骼把网格拆成几块普通网格，挂到程序化节点下；拆分按资产缓存、实例共享几何体。
  没有骨骼贴图，换枪 / 丢枪不用逐实例释放（只有带发光的实例材质由 Viewmodel 换枪时释放）。骨架指纹不符就保留程序化枪模。

## 6.6 第一人称手臂（`SM_Arms_<英雄><R|L>`）

- 每位英雄一套左右手（规格档 `fp_arm`），静态网格挂在 `Viewmodel.buildArm` 的挂点 `arm_r` / `arm_l` 上：
  右手的坐标就是枪模坐标（握把在原点附近），对所有枪通用；左手以各枪的左手握点为原点（霰弹枪挂在泵动护木上，随泵动）。
- 白模：`exportFpArm('<英雄 id>', 'r' | 'l', '<资产ID>')`；绑定 `blockout = { source = "fp", id = "<英雄 id>", attachment = "arm_r" | "arm_l" }`。
- 概念用手臂版式（`concept_layout = "fp_arm"`）：只画手、护腕、袖子，手握住一个看不见的握把，不画任何武器（道具版式会要求「不画手」）。
- 运行时没有该英雄的手臂资产时退回程序化方块手臂（英雄色袖子）；美术手臂的实例材质由 Viewmodel 换枪时释放。

## 7. 质量检查

**自动 QA（`validate`，✘ 阻塞 / ⚠ 记录）**

- 包级：文件大小 ≤ 上限；必需扩展三端可用（Draco、WebP）；LOD 数量、每级面数 ≤ 预算且逐级递减；LOD 切换距离写在节点 extras；
  身高与白模差 ≤ 6%；脚底 |y| ≤ 1 cm；水平居中；一个材质；材质与贴图命名；贴图边长 = 规格且为 2 的幂；BC / N / ORM 齐全。
- 骨骼：一个 skin；骨骼集合与游戏关节完全一致；每顶点 ≤ 4 影响；无零权重顶点；bone heat 失败顶点 ≤ 20；骨骼适配幅度 ≤ 0.25 rad 且左右对称；
  **手臂影响范围**：手臂 / 肘 / 手骨主导的顶点离骨段的 p90 ≤ `arm_radius` × 1.6（超了说明手臂骨把躯干、斗篷带走了）。
  `arm_radius` 按体型登记（瘦弱的弩手 0.09、披袍萨满 0.2、壮汉 0.24，默认 0.14），太小会让宽袖、护肩不跟手臂走，太大起不到约束作用。
  部件骨架资产不查脚底，改查「竖直中心与白模一致」（漂浮怪的尾尖、细长冠刺常被重建做短，最低点会偏但网格没有错位）。
- DCC 级：UV 在 0–1 内；UV 利用率 ≥ 50%（⚠）；UV 翻折面 ≤ 0.5%（⚠）；高模剪影对齐 IoU ≥ 0.75；投影未覆盖顶点 ≤ 45%。

**人工审核要点**

- 概念：四视图是同一个角色；比例 / 姿势贴合白模（对照图红线）；手里没有武器（武器是独立资产）；发光部位在白模的发光位置。
- 成品：贴图无明显错位 / 拉伸 / 重影；背面和侧面不是正面镜像；LOD2 远看轮廓不塌；
  姿势测试里肩、肘、膝、腰无穿插或撕裂，头部不被拉歪；举手时帽子 / 兜帽不变形；行走时衣摆、长袍不被撕开，袍内的腿不戳出来。

## 8. 引擎接入

- `AssetLibrary` 模块被导入即读清单并后台加载全部 GLB（不阻塞启动；敌人模块启动时就导入它，`main.ts` 是冻结文件，不改它）。
- 敌人与 Boss 都走 `EnemyArt.attachEnemyArt`（`StandardEnemy.init` 与 `BossBase.init` 里调用，必须在任何动画运行之前）：
  1. 身体：清单里 `bind = { source: "enemy", id: def.id }` 且没有 `attachment` 的骨骼网格。条目带 `rig.mode = "parts"` 走 `PartsRig`（6.4）；
     否则若该敌人有 `HumanoidRig`（约定存放在 `this.rig`），`SkinnedBody` 在绑定姿势下取关节矩阵求逆作 boneInverses，用 `THREE.LOD` 挂上各级 SkinnedMesh，隐藏被取代的脚本身体部件。
  2. 挂件：同一敌人下带 `attachment` 的静态网格，按挂点名挂到命名子节点上（6.1）。
  发光提示件（按 `keep_glow`）保留；受击闪白、词缀着色照常工作（实例材质登记进 flashMats）。
- **手持姿势**：蒙皮后手臂是真实网格，硬编码的手臂角度很容易让手插进武器或藏进斗篷。双手持握的武器用 `Models.reachArm(rig, side, target)`
  （两段骨解析 IK）让手跟着武器上的握点走，例如弩手的举弩瞄准：弩先摆到瞄准位置，左右手各自求解到前后握点。
- 运行时只给美术材质挂一张 RoomEnvironment 环境贴图（6.2），武器上的发光件改成加法混合、只在前摇时亮起。
- **降级**：资产缺失、加载失败、或以 `?classic` 打开 → 用程序化模型，玩法完全不受影响（判定全部基于胶囊，与网格无关）。

## 9. 新增一个资产

1. `registry.toml` 登记（ID、规格档、白模来源、材质常量、英文设定）。
2. `assetctl.py serve`，游戏 `?debug` 控制台导出白模：人形 `exportEnemyBlockout`、挂件 `exportEnemyAttachment`（6.1）、非人形 / Boss `exportEnemyParts`（6.4）。
   一次导出一个资产（单次控制台调用有超时）。
3. `assetctl.py concept <ID>` → 看 `01_concept/*_compare.png` → `approve` 或 `reject` 后带 `--note` 重出。
4. `assetctl.py run <ID> --from highpoly --to review` → 看 `05_review/*_review.png` → `approve <ID> review`。
5. `assetctl.py publish <ID>`，刷新游戏验证（对比可加 `?classic`）。

## 12. 已知限制 / 后续

- 投影贴图依赖概念四视图；顶视角、腋下等四个视图都看不到的区域是扩散补色，细节较少。
- 运行时会把保留的身体发光件（眼睛、面甲缝）沿射线吸附到美术网格表面并缩到 60%，让它们落在贴图画好的眼睛里，只负责前摇提亮。
- 目前覆盖人形敌人（`HumanoidRig`）及其挂点上的武器、非人形敌人与 Boss（部件骨架）、Boss 武器、第一人称武器（刚体部件）、第一人称手臂。
  场景道具合并在按材质分批的大网格里（顶点色 + 程序化纹理），换美术网格要改世界的渲染组织，墙体建筑又是方块风格，需要整套环境美术方案。
- 第一人称手臂是静态网格、手握成拳：所有枪共用一只右手，握把会从握拳的手指间穿过（第一人称视角基本看不到）；左手同理。
- 蜂群发射器的「弹匣」是前端火箭头，白模里全是发光件、没有实体体积，美术网格上的火箭头分到了枪身，换弹时不跟着动。
- 程序化弓弦挂在固定的弓梢坐标上，美术弓臂末端与它只是大致对齐。
- 刚体模式在关节转开时露出封口（整块一色）；过渡模式在肩、肘这类大角度关节仍有线性混合蒙皮固有的拉伸（主母举臂 p99 ≈ 2.1），
  需要更好时可加修正形状（corrective blend shape）或改用双四元数蒙皮。
- 多视图高模的表面细节比 2.1 单视图略软，换来正确的厚度；两种模式按资产选择。
- 单视图重建看不到的面（甲虫腹部、Boss 头顶）是扩散补色，游戏视角下基本看不到。
- 贴图可进一步转 KTX2（GPU 压缩纹理）降低显存。
