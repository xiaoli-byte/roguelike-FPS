## 1. 旱魃：龟裂白金裂光与日轮自发光

- **设定母题**：赤地千里的旱神，皮肤是被晒裂的焦土，裂缝里透出日火（白金）；背后的日轮就是太阳。
  - 形状不新加：发光的就是模型上本来画好的那几道金线和那只日轮，不加外壳网格、不加粒子（同 FX3 青鸟 / 狐巫的做法）。
- **读感目标**：
  - 平时：裂纹是暗皮肤上一道道细的暖白金线，远处读作「这具身体在烧」，不抢心口泉珠（弱点）的青白；
  - 日蚀：日轮熄灭、天暗下来，她身上的裂光反而烧亮——**冷**的靛黑盘（月影）对**暖**的白金裂光，玩家在 0.3 s 内读出「太阳灭了，她还在烧」；
  - 复燃（日蚀的释放帧）：裂光、日轮三层在同一帧到峰值，再 0.9 s 落回，和天色猛亮、闪光灯、爆闪星对齐。
- **遮罩**（`art/pipeline/tools/emission_mask.py`，R / G / B = 发光层 0 / 1 / 2）：

  | 贴图 | 层 | 范围 | 怎么认 |
  |---|---|---|---|
  | `T_Boss_Hanba_E`（2048²） | R 龟裂 | 皮肤上的细金线，0.53% 的纹素 | 新规则 `thin`：在 4096 底色上按色相 0.105 ± 0.065、饱和 ≥ 0.44、明度 ≥ 0.64 认金色，减掉 9 × 9 开运算留下的大色块（残衣和裂纹同色，只能靠「细」分开），再要求周围 10 纹素里暗皮肤占 ≥ 40%；按最大值缩到 2048，往外长 1 纹素 |
  | `T_BossPart_HanbaSunRing_E`（1024²） | R 轮体 | 整面白金（凹槽、铆钉留暗） | 明度 ≥ 0.82 |
  | | G 火焰芒 | 外缘（到轮轴 ≥ 2.35 m） | 新规则 `radial` |
  | | B 轮毂、八辐 | 到轮轴 ≤ 1.6 m | `radial` |

- **强度**（`Fx/GlowMask.cs` 的配色表，线性倍率，层色 sRGB）：

  | | 龟裂 `#ffe4a0` | 轮体 `#ffe9b8` | 火焰芒 `#ffb444` | 轮毂 `#fff4dc` |
  |---|---|---|---|---|
  | 平时（炽度 0.35） | 0.54 | 0.29 | 0.50 | 0.52 |
  | 聚光（炽度 1，扫射前摇等） | 0.9 | 0.65 | 1.08 | 1.3 |
  | 日蚀（日轮熄） | 1.6 | 0 | 0.9（日冕） | 0 |
  | 复燃峰值 | + 2.6 | + 0.9 | + 1.5 | + 2.0 |

  - 龟裂另跟发光通道 0（各招前摇点亮泉珠的那一路）加 0.4；倒下后 1.5 s 内熄掉。
  - 闪烁：龟裂 0.35、火焰芒 0.45（`SF_StylizedLit` 发光遮罩段自带的流动噪声），轮体 / 轮毂几乎不闪。
- **黑盘**（`SunRing`）：颜色从暖黑 `(0.03, 0.02, 0.015)` 改成冷靛黑 `(0.035, 0.04, 0.1)`；位置从轮心前 0.15 m 挪到轮毂正面之前（轮毂两面凸起、半厚约 0.6 m，原来会从黑盘中间穿出一块金色圆面）。
- **接入**：`HanbaBrain.SetupRuntimeLayer` 里 `GlowMask.Attach`；`Phase3Eclipse.Flare`（复燃）里和 `HanbaSunDriver.Flash` 同一行调 `GlowMask.Flash(Brain, 0.12, 0.9)`。日蚀程度、日轮炽度由 `GlowMask` 每帧自己读（`SunRing.Eclipsed` / `Blaze`），招式不用再管。
- **第一人称**：泉珠标记的青白和裂光的暖白金色相拉开；日蚀时裂光只在皮肤的细线上，不糊身体轮廓。

## 2. 熔心魔将：大剑正式发光遮罩

- **设定母题**：熔心大剑是一块浇了熔铜的黑铁——剑脊几道熔痕，刃口一圈熔铜带。前摇时熔铜烧亮，狂怒时刃口白热。
- **原来的问题**：`WarlordBlade` 拿底色贴图当 `_EmissionMap`、用属性块写 `_EmissionColor`，但大剑材质没开 `_EMISSION` 关键字（属性块开不了关键字），**这层自发光其实一直没画出来**，前摇 / 狂怒只看得到边光变色。底色贴图当遮罩也会让剑格、剑柄的金铜色一起亮。
- **遮罩** `T_BossWeapon_Greatsword_E`（1024²）：只认剑身（握点以下 0.32 m）的熔铜色（色相 0.07 ± 0.09、饱和 ≥ 0.56、明度 ≥ 0.62）——
  - R 剑脊熔铜纹：剑面上离 UV 岛边 ≥ 24 纹素的那部分（中间几道熔痕和分叉），3.2%；
  - G 刃口：剑面靠岛边 24 纹素以内的熔铜带 + 剑身侧面的窄条（法线 |z| ≤ 0.55），10.8%。
  - 新规则 `edge`（UV 岛内到岛边的距离）、`normalAbs`（法线分量的绝对值）。
- **强度**：走 `SF_StylizedLit` 的发光遮罩段（`_GlowMask` / `_GlowMaskColor0..1`，默认全黑跳过），不需要关键字。glow = max(前摇烧亮, 0.75 × 狂怒)：
  - 剑脊 = (0.3 + 1.7·glow + 0.5·狂怒) × 熔铜（狂怒时往白热铜偏 30%）；
  - 刃口 = (0.1 + 1.5·glow + 1.2·狂怒) × 熔铜→白热（平时 45% 白热，狂怒 100%）；
  - 剑脊带 0.4 的流动闪烁（熔铜在流），刃口 0.15。
- 魔将本体的「余烬自发光」（`WarlordBrain.UpdateLook` 写 `_EmissionColor`）也是同一个问题（`M_Boss_Warlord` 没开 `_EMISSION`），不在本路范围，记在「还缺」里。

## 3. 第三章方形裂纹贴花

- **设定母题**：熔心魔将和第三章精英砸下去，暗紫玄武岩被砸成方块石板，缝里透出熔铜。形状语言：**方块 = 土石和重量**，尖角 = 危险（裂纹末端收尖）。
- **形状**（`scripts/unity/fx_crack_ch3.py` → `Assets/Art/Fx/T_Fx_CrackCh3.png`，1024²，2 × 2 个变体，固定种子）：
  - 中间一块压塌的方坑（略转一点），坑底焦黑、中间一汪熔铜，坑沿一圈裂光、断两处；
  - 主裂纹从坑的四个角斜着往外、再从两三条边的中点直着往外，方向只取 45° 的整数倍，有的穿出外框后硬折一次，由粗（半宽 0.034–0.042）到细、末端收尖；
  - 外面一圈断续的方框裂纹（半边 0.44–0.52，八段里随机留一半多）——一圈方石板（回纹的意思）；
  - 中尺度：一块贴花里只有 6–7 道主裂纹 + 四五段石板缝，没有细碎纹。
  - 通道是数据：R 紫褐焦边（裂缝两侧 2.4 倍半宽 + 坑底），G 裂光，B 白热中线（越靠坑越热），A 到坑心的距离（蔓延用）。
- **着色器** `SF_FxCrack`（新文件，投射方式同 `SF_FxSigil`），材质 `Resources/Fx/Materials/M_Fx_CrackCh3`：
  - 色阶三阶：裂光铜橙 `(1, 0.54, 0.18)` → 冷成暗铜 `(0.72, 0.27, 0.1)`，亮芯白热铜 `(1, 0.9, 0.65)`，焦边紫褐 `(0.23, 0.14, 0.19)`（第三章：烟偏紫褐、余烬铜橙）；
  - 节拍：前 3% 寿命（6 s 寿命 ≈ 0.18 s）裂纹从坑心往外蔓延；余热从 3% 开始冷、70% 冷透只剩暗铜缝；最后 20% 淡出。狂怒（魔将 20% 换挡后）裂光往白热偏、亮芯更亮；
  - 预乘 alpha：焦边压暗、裂光 HDR 加上去，裂光不占 alpha（亮沙上靠紫褐焦边托出裂纹，熔岩暗地上靠裂光本身）。
- **池**（`Fx/CrackDecals.cs`）：同 `SigilDecals` 的池化 DecalProjector，参数走 uvScale / uvBias，同一份材质合批；同时存在的块数 = 画质贴花上限的 1/10（低 4 / 中 8 / 高 12），满了挤掉最老的。
- **接入**：
  - `Fx.WarlordImpact`（竖劈入地、跃击落地、插剑引渠、B 路新的登场落地都走它）：原来的熔铜贴花（半径 0.85r）换成方形裂纹（裂纹最远 1.1r，6 s）；贴不上时退回熔铜贴花；
  - `Fx.EliteCh3Impact`（炮仗傀儡、铁牛精英砸地）：原来不留贴花，现在留一块小号的（最远 1.25r，4 s，余热 0.8，贴不上就不留）。
  - 冲锋：刹停（`chargeStop`）是剑尖犁出的熔铜沟、撞墙（`crash`）在墙上，都不是砸地，没接；调用在 `WarlordBrain`（本轮 B 路在改），没动。
- **8 条自查**（fx-style §4）：

  | # | 自查项 | 结论 |
  |---|---|---|
  | 1 | 大形 | 方坑 + 放射主裂纹 + 方框，缩到 25% 还是「一块砸塌的方石地」 |
  | 2 | 色阶 | 裂光 / 亮芯 / 焦边三阶，冷却后只剩暗铜缝 + 焦边 |
  | 3 | 色彩 | 火的铜橙 + 第三章紫褐，不用通用裂纹的白色放射纹（那个读成旱魃的日轮） |
  | 4 | 碎纹 | 中尺度，6–7 道主裂纹，没有细碎纹和噪点 |
  | 5 | 地面 | 亮沙、雪上靠紫褐焦边；熔岩暗地上靠裂光（见拼图） |
  | 6 | 时间 | 0.18 s 蔓延到头，亮芯第一帧就在；余热约 4 s 冷透，6 s 收掉（精英 4 s） |
  | 7 | 统一 | 和魔将的熔铜冠、方铜渣、紫褐烟同一套母题 |
  | 8 | 预算 | 贴花数按画质封顶，满了挤掉最老的；不出粒子 |

## 4. 弹簧骨的动作曲线（长发回垂）

- **结论：管线早就修好了，只是没人在运行时核对过、文档还写着「不生效」。**
  - [boss-hanba.md](../boss-hanba.md) §8 写于 2026-10-21：人形关键帧 FBX 只导肌肉曲线，长发 / 残衣 / 袖垂片的曲线被丢掉，死亡后半段长发翻到头顶。
  - 第二天（10-22，`952fdf60`）`NativeClipBuilder.KeepNonHumanCurves` 已经给人形关键帧的每个 take 配了「本模型建遮罩、全部骨骼启用」的 Transform 遮罩，
    这些骨的曲线从那以后一直留在 `SK_Boss_Hanba_<状态>.anim` 里；本体 Avatar 的骨架也包含它们，人形 Animator 会照写。
  - 弹簧骨（`CreatureRig.Springs`）每帧以动画姿势里的骨端为目标（`Tip` 读当前骨骼位置），所以关键帧一播出来，手 K 的回垂补偿就在弹簧之下生效，不需要另外把关键帧交给弹簧链。
  - 所以这一路**不改导入管线**（影响最小），只补运行时核对、回归测试和文档。
- **核对**：
  - EditMode `KeyframedCurveTests`：十段手 K 片段都带三条发链、前后残衣、两袖的旋转曲线；本体 Avatar 骨架里有这些骨；
    按人形 Animator 采样死亡 / 焦裂片段，发链根节跟关键帧走（≤ 1.5°），离绑定姿势 68.0° / 31.3°（手 K 的回垂幅度）。
  - Play 模式 `review-glow`：真实的 Animator 停在回垂最大的那一帧（弹簧关），发链根节离绑定姿势 68.0°（死亡 3.23 s）/ 31.3°（焦裂 1.23 s），
    与关键帧的差 0.00°，同一帧脊柱对照 30.0° / 28.7°。
  - 拼图 `hanba-hair.jpg`：弹簧开着、停在那一帧。改前 = 发链骨每帧压回绑定姿势（= 片段里没有这些曲线时的样子：死亡时整片长发翻到头顶），改后 = 现在的样子（长发垂在背后）。
- **踩到的坑（记下来给以后的审阅套件）**：
  - 首领 Prefab 的 Animator 是 `CullUpdateTransforms`：没被任何相机看见时不写骨骼。审阅套件的临时相机在同一帧建、同一帧拍，不算「看见」——
    第一次核对就因此误报「运行时发链没跟关键帧」（连脊柱也没动）。审阅 / 核对时把 `cullingMode` 设成 `AlwaysAnimate`。
  - EditMode 测试里 `PlayableGraph.Evaluate` 不写骨骼（人形骨也不动），要用 `AnimationMode.SampleAnimationClip`。
- **其它人形资产**：`KeepNonHumanCurves` 只处理人形资产的 `Anim/Keyframed/*.fbx`（现在只有旱魃、商人）；英雄（Mixamo 库 / 采样片段）和人形敌人
  （采样片段：逐帧摆骨后 `HumanPoseHandler` 读肌肉、非人形骨写变换曲线）不走这条路。本轮没有改管线，`heroes` 套件回归照常。
