# 场景性能优化与实机记录

## Unity 固定机位基线（I4，2026-10-30）

Unity 版十二关的第一份固定机位基线，同时开启 GPU Resident Drawer（GRD）。下面「Three.js 版」各节是网页版的历史记录，协议思路相同（固定机位、预热后记录、CPU / GPU 分开看）。

### 设置

- PC 管线 `PC_RPAsset` 开 GRD（实例化绘制），同时开 GPU 遮挡剔除。
- Graphics 设置的 BatchRendererGroup Variants 设为 Keep All。不设的话，编辑器里 GRD 不启用，打包时 DOTS 实例化变体会被剥掉。
- 这些设置由 `ShowcaseSceneBuilder.ConfigureProject` 写入，每次生成关卡都会重新确认一遍；`RenderPerfSettingsTests` 检查它们没被改回去。检查范围还包括渲染路径是 Forward+，以及 SF_StylizedLit 带 DOTS 实例化。
- 移动端管线不开 GRD，需要单独测。

### 协议

用 `bridge.sh playtest perf <关卡>` 运行，套件在 `Testing/Suites/PerfSuite.cs`。

- **机位**：从玩家出生点出发，把 LevelMeta 里的必经地点按最近邻连成主线。每两个相邻地点一个机位，眼高 1.7 m，看向下一个地点，最多 8 个。机位坐标记在原始数据里。
- **相机**：单独一台测量相机，参数同玩家主相机（70°、远裁 1500 m、后处理、SMAA 高），不含第一人称层。固定渲染到 1920×1080，PC 画质。
- **采样**：关掉垂直同步和帧率上限。每档设置先把所有机位各过 20 帧，再对每个机位预热 30 帧、记录 240 帧。
- **对照**：同一组机位按三档各测一遍，测完还原管线设置。三档分别是项目设置（GRD + GPU 遮挡）、只开 GRD、关 GRD。
- **统计**：主线程和 GPU 时间来自 `CPU Main Thread Frame Time` / `GPU Frame Time` 计数器，取 P50 / P95。绘制调用来自编辑器渲染统计，含阴影。三角面含地形和阴影。
- **口径**：
  - 在编辑器 Play 模式里测，主线程包含编辑器自身的开销。
  - 帧时受编辑器刷新节流，Game 视图停在 16.7 ms 左右，所以只看主线程和 GPU。
  - 批次计数器在编辑器里读不到。
- **数据来源**：场景用库里的版本，地形、NavMesh 等生成物在本机重新生成。

参考机：RTX 5090 Laptop / Core Ultra 9 290HX。原始数据在 `art/reviews/perf-unity-20261030/perf_<关卡>.json`。

### 结论

- **GPU 遮挡剔除**：平均少画 26% 的三角面。几何越密越明显：2-2 玉阶的挡墙连排少了 45%，1-3 古城的城墙街巷少了 34%。
- **GPU 时间**：十二关的 GPU P50 均值是 2.98 ms，关掉 GRD 是 3.06 ms，差别在噪声里。这块卡远没到几何瓶颈，省下的三角面要在弱一些的显卡上才体现得出来。
- **主线程代价**：编辑器主线程多约 1.0 ms（P95 均值 8.8 对 7.8 ms），来自 GRD 的 CPU 端剔除和实例数据维护。只开 GRD、不开遮挡时主线程一样贵、三角面却不少，所以这一档不选。
- **决定**：保留「GRD + GPU 遮挡」。下一步要在中低端显卡和独立包上复测：编辑器里的主线程开销比独立包高。
- **预算余量**：最重的机位 GPU P95 也只有 7.8 ms，离 16.7 ms 的帧预算很远。

**关卡验收的静态粗估**：`LevelSpec.Budget`，按全部关卡重建时 BudgetCheck 的结果收紧：

| 指标 | 原值 | 新值 |
| --- | ---: | ---: |
| 机位面数 | 250 万 | 200 万 |
| 机位绘制 | 2500 | 500 |

- 最重的是 2-2：机位 165 万面、315 次绘制，全场景 171 万面。其中玉石挡墙一项 103 万面，这个件只有一级 LOD（5962 面），摆了 177 次。
- 3-1 / 3-2 重建时有白盒占位，换成正式件后面数会涨一些，所以全场景面数留到 300 万。

### 评估后没做的几项

- **1-3 烘焙遮挡（Umbra）**：GPU 遮挡剔除已经让 1-3 少画 34% 的三角面，GPU 也不是瓶颈。烘焙数据要入库，还要随场景每次重建，收益只剩不走 GRD 的渲染器（蒙皮敌人、粒子、非 DOTS 着色器），所以不做。等中低端卡复测显示 1-3 仍然吃紧时再加。
- **远景 impostor**：远景地标已经换成剪影替身（`LevelKit.BackdropImpostor`：不受光、不投影、无碰撞）。面数大头在中近景的城墙、挡墙、平台块，不在远景，再做八面体 impostor 收益很小。真正值得补的是 2-2 玉石挡墙的 LOD1 / LOD2，属于美术管线（智能网格那批只留了一级 LOD），单独处理。
- **地形分块 LOD**：已经有了。I1 的地形按 TerrainSpec.tiles 分块并设了相邻关系，画质档覆盖 pixelError（低 6、中 4、高沿用工程值 3）。

2026-10-04 在本机复现炼狱探索约 54 FPS。CPU 更新中位数只有 0.2 ms，主要优化对象为场景绘制。导航、射线和玩法逻辑没有改动。

### 改动

- 地面道路权重在关卡加载时烘焙为 512×512 R8 纹理（256 KiB），每像素一次采样替代原 19 段距离计算。保留原世界坐标和渐变公式，纹理随场景销毁。
- Hunyuan 岩石按 24 米区域实例合批，允许独立视锥剔除；高／中画质近处保留 LOD1，42 米外使用已发布 LOD2，并带 10% 迟滞。低画质持续使用 LOD2。各级按真实顶点适配同一碰撞包络。
- 太阳阴影保留原 2048／1024 分辨率，缓存两次刷新之间的结果，以约 30 Hz 更新动态投影。模型、敌人动画和输入仍按游戏帧率运行。关卡首帧及碰撞版本变化会立即刷新；暂停时保留上一张阴影图。
- 冻结静态陈设与远景的局部矩阵，薄雾、法阵、火焰等动态对象继续更新。

空间分块会增加少量绘制调用，但避免提交整张地图的高细节岩石；实测 GPU 和总体帧表现均改善。没有改变画质设置、显示分辨率、默认配置或已发布模型文件。

### 测量协议和结果

真实 Game、固定种子 20261004、炼狱入口、默认狐角色／蜂鸣冲锋枪，high 画质。CSS 视口 1280×720、DPR 1.5，实际绘制 1920×1080。每项 30 帧预热后记录 240 帧；保留相同视角、分辨率及预览环境。CPU 与 GPU 分开测量，GPU 使用非阻塞 WebGL 计时，无 `gl.finish`。各记录没有隐藏帧或 GPU disjoint。

| 阶段 | RAF FPS | GPU 平均 ms | 每帧三角形 | 每帧调用 |
| --- | ---: | ---: | ---: | ---: |
| 优化前 | 54.1 | 6.18 | 271,291 | 69 |
| 道路烘焙 | 56.0 | 5.78 | 271,291 | 69 |
| 分块／LOD／静态矩阵 | 58.8 | 4.79 | 187,291 | 98 |
| 加入阴影缓存 | 60.0 | 4.50 | 152,319 | 86.5 |

最终 GPU 平均耗时减少约 27%，每帧三角形减少约 44%；RAF 间隔 P95 从 33.3 ms 降到 16.8 ms。另测炼狱真实敌人战斗与 Q／E 技能约 59.5 FPS，雪境和沙寺探索均约 60 FPS；三章画面均完成检查，未出现浏览器错误或警告。

原始 JSON 与截图位于 `art/reviews/performance-20261004/`。这些结果属于以上测量场景，不代表所有分辨率与战斗负载的固定帧率。

### 开发测量与验证

访问 `/adventure-lab.html?theme=inferno&debug=1&perf=1`，点击“重新采样性能”。报告完成后锁存，不随之后的地图切换而改写；再次采样获得当前场景结果。GPU 每 7 帧采样，避免与常见阴影刷新周期混叠；不支持计时扩展时明确报告 unavailable。`#performance-readout` 的 `data-report` 提供实际 RAF、CPU、GPU、完整世界＋第一人称绘制统计。

### 地标建筑接入后的复核

同日后续增加三件本机 Hunyuan3D 建筑并细化地表，制作、发布与测量记录见 [scene-landmarks.md](scene-landmarks.md)。每图四座建筑共享资源、采用实际碰撞包络和三级 LOD，没有新增光源。相同 high / 1920×1080 协议下，三章探索均约 60.0 FPS，GPU 平均 4.27–4.71 ms；炼狱祭坛 Q / E 技能战斗最终 60.0 FPS，GPU 平均 6.41 ms、RAF P95 16.8 ms。

此次还发现同时运行的 3D 检视页会竞争渲染时间。保留探索 48.3 FPS、首次技能战斗 54.4 FPS 和持续战斗 52.0 FPS 的原始记录；临时移除自有场景预览即可恢复 60 FPS。最终场景播放预览限制为 30 Hz，暂停预览在操作后的 600 ms 内收敛，再停止更新和绘制；所有控件、尺寸变化、页面重新可见与 WebGL 恢复均能重新绘制，并等待真实地表原图加载。播放中的武器、怪物与实际游戏保持正常 RAF。恢复全部页面后，战斗测量仍为以上 60.0 FPS。

最新全量 **98 项测试通过**、生产构建通过；源资产本机哈希审计 10 项通过。新增原始数据和画面在 `art/reviews/landmarks-20261004/`，旧轮次的测量和测试数量保留供追溯。这些结果仍限于本机上述负载，并非所有战斗的帧率承诺。
