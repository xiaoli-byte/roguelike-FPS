# 关卡平面设计与场景装配 · LD-02 / ART-03

2026-10-04。**用户已试玩认可白盒，十五张独立布局进入场景美术阶段，并成为正常游戏的默认地图。** 美术沿用已验证的通道、掩体和遭遇空间；复用本机 Hunyuan3D 成品墙、岩壁与地标，并为冻湖和输渣线补充新生成的栈桥。`/whitebox-lab.html` 可在同一关切换场景美术与技术白盒，仍使用真实移动、碰撞、导航和遭遇流程。

第二轮补充本机 Hunyuan 货运绞盘、逐房区地面材质及入口/路口/补给细节，并重排角色眼高的主景视线。工作台可选“美术观察点”后进入“净视预览”，Esc 返回；本轮资产来源和实机记录见 [场景美术记录](../gunfire-scenes.md)。

第三轮增加本机 Hunyuan 商棚、短船和渣车，分别装配六个有对应用途的房区。冻湖原 U 形修船槽采用低护岸与实际船体，局部射击遮挡跟随固定 LOD1 网格；原 8m 移动阻挡、导航、通道和遭遇仍保留。远山环改以地图边界中点定位。

## 设计方法与范围

先定本关体验和遭遇节奏，再画空间节点、实际可走轮廓、通道宽度和视线关系；随后以真实角色与敌人进行白盒试玩，迭代通过后才投入场景美术。此流程参考 [Epic 的草图与关卡白盒指导](https://dev.epicgames.com/documentation/unreal-engine/designer-01-project-setup-and-level-blockout-in-unreal-engine?lang=en-US) 和 [The Level Design Book 的白盒流程](https://book.leveldesignbook.com/process/blockout)。这些资料支持尽早验证尺度与游玩感受，并不规定统一的地图模板或固定尺寸。

本轮采用平层方案，保留步行、冲刺、可选战斗与物资分路；不依赖钥匙门、平台跳跃或新解锁机制。高台与坡道需要在白盒阶段另做剖面及视线验证。空间自由度来自绕行、换入口、风险与奖励的取舍，首领关则以场内连续换位为主。

## 图纸约定与验收边界

- 坐标单位为米，二维 Y 轴朝图纸下方；运行时转换为 `x = 图纸X - 宽/2`、`z = 图纸Y - 深/2`，不随机旋转。
- 房区多边形与带宽通道的并集构成可走地面；蓝灰区域不可通行；斜线实体代表 2.6m 遮挡占位。技术白盒按 0.5m 格采样，斜边最大偏差约 0.36m；可见几何与碰撞一致。外侧实体暂高 8m，防止现有二段跳借掩体翻越；正式岩体、建筑或深谷的形态与高度留待剖面和美术设计。
- 蓝线代表主路通道，房区内自由移动，不代表精确导航轨迹；绿线为可选路线，紫线为回接。所有通道暂可双向通过，箭头表示设计推进方向。
- 红字为小队阵位及朝向，不是精确刷怪点。每组的兵种、数量和激活时机在图册下方列出；白盒使用各房区的安全生成位置，保留玩家安全距离与刷新预警，并限制同时激活的遭遇。
- 二维验证覆盖：房区图连通、主线顺序、端点落地、通道中心线净空、未声明的通道交叉、设计射线穿实体、关键点可达性。可达性使用 0.5m 网格，玩家半径 0.35m；另核对半径 1.25m 的关键点与实际首领半径出生净空。
- 图纸校验无法证明导航 AI、第一人称可读性、跳跃视线、弹道安全或战斗难度合适。每图附有专属白盒检查问题；通过几何检查也不能直接开始批量美术制作。

## 白盒验证记录与边界

几何测试 **6 项通过**：15 张运行时底图与图纸 JSON 一致；178 个检查点（关键点与房区观察点）及交互、敌方站位被真实 1m NavGrid 精确到达；玩家碰撞体按行走与冲刺速度步进到达各检查点；所有通道中心线双向通过；检查首领出生体积、出口净空与借掩体二段跳的外围阻挡。每图合并为 59–322 个碰撞盒、50–265 个地面矩形。

流程测试 **8 项通过**，覆盖 15 张普通/首领图、12 个精英分支和 30 个商店/宝藏情形，检查真实 StageDirector 与 WaveRunner 的触发、刷新、奖励和离场调度，以及出界恢复安全距离、出场点被玩家占据时的等待提示。此类自动化流程推进不等同于完成这些关卡的实战平衡试玩。

浏览器已用真实移动控制器按图纸主路折点走过沙寺 1（132.2m / 17.2s）、沙寺 5（126.3m / 16.3s）、霜山 3（137.9m / 17.8s）和熔火 3（166.3m / 21.5s），终点误差均小于 0.33m。十五关浏览器碰撞与导航探针均通过；沙寺首领场验证了靠近触发和辅助清场后的完成状态。这些是无敌检视下的路线记录，不是通关时间或实战平衡验收。全量测试 155/155、生产构建通过；证据位于 `art/reviews/whitebox-20261004/`。

工作台使用独立局外存档 `gunflame.whitebox.meta.v1`，美术/白盒切换不影响隔离，调试清场不会增加正式存档的魂晶或生涯记录。正常游戏使用正式存档。识路、近远程换位、炮击躲避、首领追击和长期帧率仍需随美术迭代持续检查。

## 当前阶段与后续顺序

本轮艺术版验证：全量 **172/172 测试**与生产构建通过；十五图浏览器碰撞/导航探针通过。冻湖与输渣线艺术版分别实走主路 137.9m / 17.8s、166.3m / 21.5s；工作台美术/白盒切换保持同一通路。两张重场景的 1080p 高画质短时采样约 59.8–60.0 FPS，条件和限制见 [场景验证记录](../gunfire-scenes.md#本轮实机与性能记录)。

1. 已完成：独立平面设计、技术白盒、真实移动与遭遇接入；用户试玩认可后开始美术制作。
2. 当前场景：十五关各自编排峡口、城街、寺院、冻湖和炉场地标；Hunyuan 成品等比实例化，按分块 LOD 控制渲染成本。桥板使用同一份 Hunyuan 模块，其三个 LOD 的实际网格均检查板面连续性。
3. 对照工作台检查遮挡边界、转角识路、桥面接缝及各章光照，再在实际游戏更新与战斗中采样性能。几何与流程通过不等于战斗平衡已完成。
4. 后续美术修改继续遵守批准的通道净宽、2.6m 掩体与外缘阻挡。源图纸变更需先回到白盒验证；不得为了摆模型压缩通路。
