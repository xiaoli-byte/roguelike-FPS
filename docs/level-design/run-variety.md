# 每局不同的地图（2026-11-08）

用户要求：「玩家每开一局都是不同的地图」。

Unity 版的关卡是 16 张手工开放大图（地形、套件、光照、构图都按概念图逐张调过），原来每局都按 1-1 → 1-2 → … 的固定顺序、固定走法打一遍。
这一轮不推翻手工地图、也不改成程序生成，而是在两层上让每一局不一样：

1. **路线层**：每章的开放大图按局种子洗牌，这一局先打哪张、后打哪张都不同。
2. **图内层**：同一张图有几种「走法」（布局变体）——从不同的地方进、从不同的地方出、按不同的先后打据点，据点的编制和奖励跟着走法调。

两层都只由局种子决定：同一局里重来本关、暂离后继续征程，看到的还是同一条路线、同一种走法。

## 1. 每局路线（`RunRoute`）

代码：`unity/Assets/Game/Scripts/Core/RunRoute.cs`，存在 `RunState.route`（每个槽位用哪张图，规划表编号）。

- 章的顺序不变：赤沙古道 → 昆仑雪墟 → 祝融火狱 → 雪域天路，首领关永远是章末。
- 每章的开放大图洗牌，**带首领前补给营的开放图钉在本章最后一张开放图的位置**（第一章 1-3 沉沙古城的寺院塔院），补给永远在首领之前。
  - 第一章：古道 / 雅丹两种先后（沉沙古城钉住）；第二、三章：三张图六种先后。
- 槽位的编号、关序、难度按**位置**算：这一局的第一张开放图永远是难度 1.00 的「1-1」，不管抽到的是哪张图；场景、标题、首领、补给营、清关奖励跟着**地图**走（`StageSpec.map`）。
- 场景还没建好的图不进路线，后面的槽位往前补（第四章现在只建了 4-1、4-3：这一章是「4-1」「4-2」两个槽位）。
- 洗牌用独立随机流 `route`，每章各自派生子序列：掉落 / 刷怪多掷几次、第四章多建一张图，都不改变前三章的顺序。
- **不洗牌**的情况：生涯第一局（新手按设计顺序先走 1-1 古道认识敌人）、调试局（直接打开关卡场景）、测试拼的局、加这个字段之前的旧档。
- `RunPlan.First / Get / ForScene / Final / Playable` 在有路线的局里按路线答；`RunPlan.Next / IsFinal / IsLast / InPlay` 按槽位所属的路线答；
  `RunPlan.Stages / Canonical` 永远是规划表本身（构建设置顺序、经济投影、关卡构建器用）。

### 1.1 图池（备选图）

参考《雨中冒险 2》每个关卡位置有 2～3 张图随机抽：每章再加一张备选图（`RunPlan.Pool`，编号「章-字母」），
洗牌时和本章主图一起抽，抽满本章的开放图槽位（槽位数 = 本章建好的主图数，所以一局的关数不变）——一局可能见不到某张主图、却见到备选图。

| 编号 | 图 | 场景 | 题材 |
|---|---|---|---|
| 1-A | 千佛崖 | `L1_A_GrottoCliff` | 莫高窟式断崖石窟：崖脚 / 窟檐 / 崖顶三层，大佛窟、崖顶塔院、宕泉河洲（设计稿 maps/1-A.md） |
| 2-A | 玄冰裂谷 | `L2_A_Crevasse` | 开阔古冰川：主裂谷 + 四道窄缝、雪桥 / 冰桥、冰塔林、冰碛垄、冰川源头白毛风（maps/2-A.md） |
| 3-A | 赤焰灰原 | `L3_A_AshPlain` | 火山灰原：熔岩河 + 支流切出三块陆地、六道玄武岩堤、柱林、火口丘、祝融残殿、熔渠铸坊（maps/3-A.md） |

三张都已建好（2026-11-08）：各 4 个必清据点（每个 2–3 波）+ 4 个驻守点 + 8 个入场点 + 两种走法，关卡验收 0 不合格。
据点编制比同章主图多：1-A 必清 59 只（1-3 约 40）、2-A 编制合计 112 只（2-3 约 45）、3-A 必清 72 只（3-1 约 46）。

- 场景没建好时不进图池，路线照旧只在主图里洗。
- 备选图不在主线上：生涯第一局 / 调试局不走、经济投影和平衡表不算它们；构建设置照样打进包（本章有主图在路线上就启用）。
- 补给营那张照样钉在本章最后。

## 2. 图内布局变体（`LevelLayout`）

代码：`unity/Assets/Game/Scripts/World/LevelLayout.cs`；构建部件 `unity/Assets/Pipeline/Editor/Levels/LevelKit.Layout.cs`。

关卡场景里每种走法的出生标记、出口祭坛 / 传送门都摆好，`LevelLayout` 在所有关卡物体的 Awake 之前按这一局抽中的变体：

- 只留这个走法的出生点和出口（别的停用：`PlayerSpawn.In` 只认在场的出生标记，行旅图不标停用的地点）；
- `only` 里的物体只在这个走法里在场（变体专属的出口祭坛），`hide` 里的物体这个走法里藏起来（给祭坛让位的杂物）；
- `requires` 改写据点先后（反着走时把「② ③ 要求 ①」反过来）；
- `sites` 改写据点的编制和肃清奖励：**难度曲线跟着走法走**——先打的据点用开场编制、给第二把枪，最后打的用终局编制（精英）。

进关横幅的小字写这一局的走法（「1-1 · 自驼队营地入」），让玩家知道这次换了进出口。

抽法：这一局有路线时按随机流 `layout`（种子 + 槽位编号，每次现算，不受这一局里之前掷过几次影响）按权重掷；没有路线的局用第一个变体（主走法 = 设计稿走法），所以冒烟测试、直接打开场景照旧走设计稿路线。
`LevelLayout.Force = "<id>"` 可以指定（测试）；调试命令「换一种走法」（`next_layout`）换下一种并重来本关。

变体专属的祭坛在 NavMesh 烘焙**之后**再摆：主走法里它是停用的，不在导航网格上挖洞；用上它的那一局由 `NavMeshObstacle`（carve）运行时挖。

## 3. 战斗导演：怪要多（`CombatDirector`）

用户 2026-11-08：「射得爽是指武器牛逼，怪物少了满足不了玩家的爽感。」参考《雨中冒险 2》的 Combat Director，开放大图里据点之间也持续有怪。

代码：`unity/Assets/Game/Scripts/Encounters/CombatDirector.cs`（[GameSystem]，挂在 Core）。

- **游荡怪群**：进关 25 s 热身后开始，在玩家视野外（优先背后 / 侧面）24–42 m、导航网格上、走得到的点刷一群，地面先亮 0.8 s 出生圈。
  - 间隔随这一关待的时间缩短：22 s → 每分钟 −1.5 s → 最短 10 s；群大小 3 → 每 1.5 分钟 +1 → 最多 7 只；精英概率 5% → 每分钟 +2.5% → 最多 25%（一群最多一只精英）。
  - 怪物表 = 这张图各据点编制里出现过的敌人，按出现次数加权（题材、模型都对得上，新图不用另配表）；熔岩里游的、首领不刷；重型（耐久 ≥ 表中位数 2.5 倍）一群最多一只。
  - 刷出来的怪直接追玩家（敌人 AI 本来就全图锁定玩家）。
  - 场上游荡怪最多 12 只；据点交战中、玩家在补给营安全区附近（30 m）、关卡目标完成之后、玩家阵亡时暂停（计时顺延，不攒着一起刷）。
  - 只在开放图里跑，首领关不跑。
- **据点加量**：据点开打时克隆的编制里，普通单位（非精英、条目 ≥ 2 只）× 1.5（向上取整）；精英和单只的重型不变；不改场景里的模板。
- **哪些局开**：正式的局（主菜单出征，`RunState.dev = false`）开；调试局（直接打开场景、冒烟测试）缺省不开，免得打乱按固定编制写的测试。
  `CombatDirector.Force` 或调试命令「游荡刷怪开关」（`combat_director`）可以在调试局里打开。
- 击杀奖励照常（灵石 / 魂晶会比原来多，经济投影没算游荡怪，之后看实玩再调）。

### 3.1 怪摆在哪：驻守点 / 据点 / 入场点

用户 2026-11-08：「要考虑哪些地方能够安排怪物，哪些作为据点刷多轮怪物，哪些地方作为怪物入场点。」每张开放图的怪分三类地方，关卡构建器各自摆好、写进设计稿：

| 类别 | 是什么 | 怎么摆 |
|---|---|---|
| 驻守点 | 据点之间、路线 / 兴趣点上的路遇小队：开局就站在场上、玩家先看见，走近 / 开枪整组苏醒 | `EncounterSite.AsRoadside` + 条目 `Via(Ambush)` + 埋伏站位；可选、不计目标、不落宝箱；离据点触发圈和出生点够远 |
| 据点 | 必清的多波场地（2–3 波），清完给奖励 | `EncounterSite`；波次从场地自己的出生站位进场（`SpawnAnchor`：现身 / 跃下 / 增援门 / 熔岩爬出 / 飞临…，合乎地形） |
| 入场点 | 据点之外持续涌来的游荡怪群从哪进来 | `MonsterEntry`（`LevelKit.Entry`）：沙丘 / 岩丘背后、峡口、门洞、崖顶跃下、熔岩边、飞临点；离出生点 ≥ 30 m；验收 `LevelKit.CheckEntries`（在导航网格上、走得到） |

战斗导演只从入场点刷游荡怪群：挑离玩家 22–75 m、走得到、优先玩家看不到的入场点，按入场方式播预告和入场动作（跃下从起跳点跳到落点、飞临从入场点飞进来、熔岩爬出 / 余烬起身 / 增援门同据点的声光）。
还没摆入场点的老图暂时退回随机落点（验收会提醒）。

进度（2026-11-08）：第一章 1-1 / 1-2 / 1-3、第二章 2-1 / 2-2 / 2-3 各摆了 4 个驻守点和 6–7 个入场点，部分据点波次改成跃下 / 增援门 / 飞临；
三张备选图建图时按三类摆好。第三章老图（3-1 / 3-2 / 3-3 本来就有路遇小队）另有会话在改、第四章没建完，入场点之后补——这些图游荡怪暂时走随机落点。

## 4. 验收

- EditMode：`RunRouteTests`（洗牌规则、补给营钉位、同种子同路线、各章独立、没建好的图往前补、RunPlan 跟着路线走、存档 / 重来快照带路线、试玩开关、变体抽法）。
- 关卡验收（`bridge.sh level 1-1 / 1-2 / 1-3`）：每种走法一个 PlayerSpawn；主线路点里加了变体的出生 → 出口；审核截图加了变体的出生 / 出口机位（`RevSpawn` / `RevExit` / `SpawnNE` / `SpawnW`）。
- EditMode：`RunRouteTests.Pool_AltMapsJoinTheShuffle_SameSlotCount`（图池：槽位数不变、补给营钉住、备选图都抽得到、不洗牌时不走备选图）。
- 实机：`bridge.sh playtest director`——调试局缺省不刷；打开后怪物表 = 据点里出现过的敌人、立刻刷一群（玩家 18 m 外、在导航网格上）、热身后自然刷、据点普通单位 × 1.5 且不改模板、据点交战中不刷。
- 实机：`bridge.sh playtest layout`——从 Core 走正式「新的一局」：路线第一个槽位、按路线进下一关；每张有变体的开放图（主图 + 图池）逐个走法进一遍（出生点、在场的出口只有一个、先后 / 编制 / 奖励改写、关卡目标只收在场的场地、行旅图只标一个出口），不指定时重来本关走法不变。
