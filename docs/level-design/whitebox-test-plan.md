# 关卡场景与白盒对照工作台

入口：`http://localhost:5259/whitebox-lab.html`。默认呈现场景美术并停在俯视图，游戏时间暂停；页面与正常游戏使用同一批 LD-02 十五关布局。呈现选择框可切换技术白盒（`look=whitebox`）和 Hunyuan 场景装配（`look=art`），切换会重置本关。工作台两种呈现都使用独立试玩存档，不影响正式生涯。

## 观察方式

- **俯视**：正交全图。查看实际碰撞白盒、路线与玩家位置；切回俯视会停止自动步行并暂停战斗时间。
- **第一人称观察**：使用真实玩家相机与游戏更新，不申请鼠标锁定。可以用侧栏快速定位，再查看转角遮挡与敌人。
- **净视预览**：沿用第一人称观察，收起工具栏和 HUD；右上角“返回工具”或 Esc 恢复。游戏仍更新、敌人仍行动，只有俯视才暂停时间。
- **进入试玩**：锁定鼠标并收起工作台。WASD 移动、空格跳跃、Shift 冲刺、鼠标射击、R 换弹、F 交互、Q/E 技能；Esc 释放鼠标，返回工作台。

无敌检视默认开启，可关闭。该选项只影响受伤，敌人的导航、攻击、投射物与遭遇激活仍使用正式游戏逻辑。快速定位会传送玩家，因此它的结果不能被记录成步行通过。

快速定位分为“通道与战斗检查点”和“美术观察点 · 角色眼高”。后者复用已验证的安全站位，并朝向该关的主景、入口标记、路口设备或补给龛；不增加游戏导航点。切回技术白盒后只保留原空间检查点。

## 可重复的验证

1. 切换章节、地图和分支。核对标题、平面图链接、实际空间与探针报告中的地图编号一致。
2. 查看自动执行的 **全部通道碰撞检查**：独立的 0.7m × 1.8m 角色碰撞体按原图中心线以不超过 0.12m 的步距移动；关键点通过实际 NavGrid 从入口寻路。报告只代表静态通行与导航终点检查，不代表玩家试玩。
3. 在自动步行路线选择框选 **完整主路（按图纸折点）**、某条支路或当前位置到检查点，然后点击 **实际步行到选点**。玩家从当前位置出发，由已有 Input.simulateKey 和 PlayerController 处理加速、惯性、碰撞与相机；整个过程不改速度、不传送。需要从入口开始时，先明确使用快速定位回入口。沿路正常触发遭遇。手动按 WASD、切换地图、切换观察方式或点击停止都会取消自动输入。
4. 完整主路依次经过图纸规定的通道折点；支路模式先从当前位置步行到该支路起点，再顺向走到终点。也可分别选补给或房区，再从该点步行到出口。记录实走距离、耗时、停滞位置和遭遇顺序，不能仅凭抵达出口宣称支路已走通。
5. 进入第一人称试玩，逐项回答侧栏的本关验证问题。重点检查最窄转角、跳跃与冲刺、绕行接敌方向、炮手跨区曲射以及首领换位空间。
6. 在单个活跃游戏页面中采样性能，保存状态、分辨率、敌人数与完整报告。俯视暂停时的性能不能代表战斗性能。

## 记录接口

所有自动化数据同时显示在工作台 DOM，浏览器验收无需读取隐藏游戏对象：

- `#wb-status`：地图编号、玩家位置、地面状态、敌人数、遭遇列表与观察方式。
- `#wb-status[data-ray-windows]`：已激活的局部网格射击代理数。美术版冻湖三栈在资产就绪后为 1；技术白盒与其余地图为 0。原移动碰撞和导航不因它改变。
- `#wb-walk-status`：实际步行状态、耗时、距离、终点误差和失败原因；`data-report` 为 JSON。
- `#wb-audit-status`：各通道与关键点结果；`data-report` 为 JSON。
- `#wb-performance`：240 帧报告，区分 GPU 不可用与有效计时；`data-report` 为 JSON。

只有实际检查过的项才记录为通过。人工空间体验、战斗难度和正式美术表现需要分别评估。
