# Unity 版性能：固定机位基线、剔除与预算（I4）

Three.js 版的性能记录在 [performance.md](performance.md)，这份只管 Unity 版（`unity/`，URP 17，Unity 6000.5.4f1）。I4 的定义见 [unity-parity.md](unity-parity.md) 第 4 批。
I4 由两台机器上的两个会话分别做过，2026-10-30 合成这一份：本机（RTX 3070 台式机）和另一台（RTX 5090 Laptop，第 4 节）的数据都留着。

结论：

- **Unity 版是 CPU 主线程瓶颈**。本机 12 关、高档、1920×1080 下，GPU P95 最重 5.4 ms（2-2 玉阶月台），主线程（不含编辑器那段）P50 3.8–10.7 ms、P95 最重 14.0 ms（2-1 战斗机位；同一机位另一次 9.0 ms，编辑器里的时间受机器负载影响大）。
  画质档主要省 GPU（低档 GPU 减半、绘制调用减到三分之一），所以低档和高档的整帧差不多——这不是画质档没生效。
- `playtest fx` 压力项从 9.5 / 8.3 ms 涨到 11.7 / 11.4 ms，**不是代码退步**：同一份代码在重启过的编辑器里是 9.5 / 9.0 ms。原来的测法把编辑器自己的开销、截图那一帧、机器负载都算进了帧时间。测法已改，另修了一处真实的 CPU 热点（HUD 重绘）。
- **GPU 常驻绘制（GPU Resident Drawer）和 GPU 遮挡剔除默认关**。两台机器的数据一致：GPU 时间没有收益（5090：GPU P50 2.98 对 3.06 ms，噪声内），主线程却变贵（5090 +1.0 ms；本机开 GRD +0.6–2.0 ms，再开遮挡 +1.1–1.9 ms）；
  GRD 也不认按图层的剔除距离。对照模式留在 `playtest perf-grd`，以后在打包的游戏里复测。1-3 的烘焙遮挡（Umbra）也对照过，主线程 +0.3–1.1 ms，不用。
- 远景 impostor 不做（模型不减面、只发一级 _LOD0），远处的负担交给**按图层的剔除距离**（`CullLayers`）：小件 / 散布两个图层，高档剔到雾里才剔，画面不变。
- 预算写进 L5（`PerfBudgetCheck`，固定机位估算）和性能套件（运行时计数、GPU / 主线程 P95），阈值在 `Spiritfire.Game.PerfBudget` 一处，12 关都在预算内。
- **枪模不再是叠加相机**（第二批 E 路，2026-11-01，5.6 节）：主相机里用一个枪模 pass 画 FirstPerson 层，玩家相机栈只剩一台相机，主线程 P50 中位数少约 1 ms（第 1 步裁剪之后再少 0.83–1.36 ms）。
  顺带查出并修掉了一个老问题：以前世界被主相机和枪模相机**各后处理一遍**。现在是单遍后处理，前三章的 Volume 重新拟合到原来第一人称看到的样子，枪模 / 手 / 特效用 `FirstPersonExposure` 补偿回原来的亮度。

## 1. 测量协议

**套件**：`bridge.sh playtest perf [关卡 id]`（只测这一关，默认 1-1）；`perf-ch1` / `perf-ch2` / `perf-ch3`（一章 4 关，从本章第一关进，之后 `SceneFlow.GoTo`，一章约 250 s）。
代码在 `unity/Assets/Game/Scripts/Testing/Suites/PerfSuite.cs`，计时在 `Testing/PerfProbe.cs`，机位规则在 `Core/PerfViews.cs`。
对照套件：`perf-grd`（GPU 常驻绘制 / GPU 遮挡）、`perf-cull-ch1/2/3`（按图层剔除距离，带改前 / 改后截图）、`perf-fx`（fx 压力项的分段拆解，第 2 节）、
`perf-fp`（玩家自己的相机：叠加枪模相机 / 裁剪 / 单相机 + 枪模 pass，5.6 节）。第一人称画面的对齐：`fp-grade-ch1/2/3`、`fp-look-ch1/2/3`、`fp-shots`（5.6 节）。
注意 perf / perf-ch 的测量相机**不带枪模**（只看世界），所以第一人称的改动只在 perf-fp 里看得出来。

**机位**（`PerfViews`，L5 的 `PerfBudgetCheck` 用同一份规则；全由关卡数据推出来，关卡布局不变机位就不变，坐标写进结果文件）：

| 机位 | 规则 |
|---|---|
| 出生 | `PlayerSpawn` 的位置和朝向 |
| 中段远眺 | 离俯视图中心最近的地点（场地 / 营地 / 祭坛 / 出口 / 首领场；有别的地点时不用战斗场地），往出生点一侧退 8 m，看离它最远的地点 |
| 战斗 | 离出生点最近的必清场地（首领关：首领场）往出生点一侧退 10 m 看中心；周围 4 m 摆 6 只本关场地里最常见的敌人（首领关用 jerboa_blade），AI 停住、着火 + 感电；玩家站在机位上暴击连射，采样期间两次 3 m 爆炸 |
| 主线 1…N | 出生点 + 必经地点按最近邻串成一条线，相邻两点一个机位（站前一点、看后一点），最多 8 段（另一台机器那份套件的机位，第 4 节） |

站点贴到 NavMesh（6 m 内最近点，不会落到屋顶上）。藏宝点不算地点（支路、常在角落）。

**测量**：

- 单独一台测量相机（参数同玩家主相机：70°、远裁 1500 m、后处理、SMAA 高，不含第一人称层），固定渲染到 1920×1080，和 Game 视图大小无关。测量期间关掉其它相机、垂直同步和帧率上限，测完还原。它挂 MainCamera 标签，按图层剔除距离照常作用在它上面。
- 每关先停掉场地、首领遭遇（机位附近不会真的开战、不放首领登场）和天气导演：1-1 的沙暴、3-1 的落灰按时间循环，会把雾拉近、改主光，让两次采样不可比。玩家无敌。
- 高 / 低两档。换档后先把每个机位看 0.5 s（着色器变体编译、贴图上传、阴影图重建），再逐个机位预热 1 s、采 2 s（`PerfProbe`，ProfilerRecorder）：
  - 主线程：`CPU Main Thread Frame Time` 的 P50 / P95（游戏自己的主线程，不含编辑器那段），另记 `PlayerLoop` 均值；渲染线程：`CPU Render Thread Frame Time` P95；GPU：`GPU Frame Time` P50 / P95；
  - 绘制调用：Unity 6.5 起按路径分开计（SRP Batcher / 普通 / 实例化 / BRG …，旧的 Draw Calls Count 没了），表里是合计；SetPass、三角面、投影体（Shadow Casters）都是整帧均值，含阴影级联和后处理；
  - 视锥内渲染器：测量相机视锥 + 远裁 + 按层剔除距离里的渲染器数（估算，不含遮挡）；每条记录还附同一机位的 L5 估算（`est*`）；
  - 整帧 P50 / P95（`Time.unscaledDeltaTime`，编辑器里的整帧）只作记录，含编辑器自己约 2 ms。
- 每关写 `unity/Assets/Art/_Review/perf_<关卡>.json`（机器、坐标、每个机位每一档一条记录），`python scripts/unity/perf_table.py` 出表（`--views` 每个机位一行，`--summary` 出各项最大值）。
- 采样前确认 bridge 队列里没有别的试玩、机器上没有 Blender / 另一个 Unity 在跑。编辑器里的时间对机器负载很敏感（第 2 节），只跟同一台机器、同一协议的上一次比；预算只看主线程、GPU 和计数，不看整帧。

## 2. `playtest fx` 压力项的「退步」

**现象**：压力项（8 只敌人全身着火感电 + 暴击连射 4 s + 3 次爆炸）早先是高档 457 颗粒子 / 9.5 ms、低档 245 / 8.3 ms，
最近是高档约 384 / 11.7 ms、低档约 192 / 11.4 ms，低档和高档差不多慢。

**历史**（bridge 回应里留着的 40 次 `playtest fx`，同一台机器）：

| 时间 | 高档 平均帧 | 低档 平均帧 | 说明 |
|---|---|---|---|
| 10-25 14:10–15:07（9 次） | 9.2 – 30.7 ms | 8.3 – 35.4 ms | 同一份代码一个小时里差三倍；9.5 / 8.3 是其中 15:07 那一次 |
| 10-25 晚 – 10-27 | 10.1 – 12.1 ms | 9.8 – 16.0 ms | |
| 10-28 – 10-29（16 次） | 10.8 – 14.6 ms | 10.3 – 12.9 ms | 编辑器连续开了好几天、同时给十来个会话排队 |
| 10-30 重启编辑器后 | 9.5 ms | 9.0 ms | 和 10-29 23:38 的 11.9 / 11.4 是几乎同一份代码 |

**拆解**（新套件 `playtest perf-fx`：同一场景重放压力项，期间不截图，`PerfProbe` 分段记；数字是同一会话里的一次）：

| 对照 | 整帧 | 主线程（PlayerLoop） | GPU | 绘制相关 |
|---|---|---|---|---|
| 空场 · 高 | 5.6 ms | 4.1 ms | 1.5 ms | |
| 空场 · 低 | 5.3 ms | 3.8 ms | 0.7 ms | 三角面 705k → 341k、投影体 159 → 36 |
| 压力 · 高 | 9.2 – 9.7 ms | 7.4 – 7.6 ms | 1.6 ms | |
| 压力 · 低 | 8.1 – 8.5 ms | 6.3 – 6.6 ms | 0.7 ms | 三角面 815k → 313k、投影体 173 → 31 |
| 压力 · 高 + 第 90 帧截图（原测法） | 9.5 – 10.2 ms | 7.6 – 8.1 ms | 1.7 – 1.9 ms | 截图那一帧 115 – 125 ms |
| 压力 · 高 + 关后处理 | 8.6 ms | 6.7 ms | 1.2 ms | |
| 压力 · 高 + 关阴影 | 9.1 – 9.5 ms | 7.1 – 7.4 ms | 1.3 ms | |
| 压力 · 高 + 关水面 | 9.3 ms | 7.4 ms | 1.5 ms | 测试场只有 1 块水面 |

整帧比主线程多出的约 1.9 ms 是编辑器自己（Inspector / Scene 视图重绘等），打包后没有。主线程里：URP 两台相机（主相机 + 枪模叠加相机）的 RenderGraph 录制、剔除、提交约 2.5–3.2 ms，
UI Toolkit 重绘 1.2–1.4 ms（空场 0.1 ms），脚本 Update / LateUpdate 1.3 ms，音频、粒子、动画、物理合计约 1 ms。

**原因**：

1. **这个压力项是主线程瓶颈**。GPU 只有 1.6 ms（高）/ 0.7 ms（低）。画质档改的是渲染比例、MSAA、阴影距离 / 级联 / 分辨率、SSAO、粒子密度——主要省 GPU，主线程只省约 1 ms，
   所以低档和高档几乎一样慢。画质档是生效的：低档的 URP 资产确实是渲染比例 0.7、MSAA 1×、阴影 45 m / 1 级、lodBias 1，GPU 和三角面都减半。
2. **原来的测法把不该算的算进去了**：编辑器开销（约 1.9 ms / 帧）；4 秒窗口里第 90 帧截图（1600×900 渲染 + 读回 + PNG 编码，单帧 115 ms，均摊 0.3 ms 左右）；
   而且编辑器里的帧时间对机器负载非常敏感（上表同一份代码 9.2–30.7 ms）。10-26 起的 11–12 ms 是长时间运行、同时排队十来个会话的编辑器，重启后同一份代码回到 9.5 / 9.0 ms。
3. 之前的嫌疑：后处理（F4）真实但不是退步（关掉主线程 −0.7 ms、GPU −0.4 ms，色调映射是观感的一部分，不关）；水面（W4）在测试场只有一块，开关没有可测的差别；画质档没生效——排除。

**修法**：

1. `FxSuite` 压力项改用 `PerfProbe`：截图那一帧和它后面一帧（物理补步）不计；分开报整帧、主线程（PlayerLoop）、渲染线程、GPU。低档和高档的差别在 GPU 一栏，一眼看得出画质档生效没有。
2. HUD 的伤害数字、敌人血条每帧改位移 / 缩放 / 透明度，以前每帧在 CPU 上重排顶点；给这些元素加 UI Toolkit 的 `UsageHints.DynamicTransform` / `DynamicColor`，
   变换和透明度交给着色器：压力项里 `UIElements.UpdateRenderData` 0.85–0.96 → 0.62–0.72 ms，`UIR.NudgeVertices` 0.16 → 0.04 ms，`UIElementsRepaintPanels` 1.27–1.40 → 1.00–1.13 ms。画面不变。
3. 新增 `playtest perf-fx`，以后再怀疑帧时间，先跑它看是哪一段。

**改前 / 改后**（`playtest fx` 压力项，同一会话）：

| 测法 | 高档 | 低档 |
|---|---|---|
| 10-29 原测法（长时间运行的编辑器） | 384 颗 / 11.7 ms | 192 颗 / 11.4 ms |
| 10-30 原测法（重启后的编辑器，改动前） | 395 颗 / 9.5 ms（最长 115 ms） | 197 颗 / 9.0 ms（最长 117 ms） |
| 10-30 新测法（改动后） | 381 颗 / 整帧 9.1 ms = 主线程 7.2 + 编辑器约 1.9；渲染线程 2.6、GPU 1.8 ms；最长 18.5 ms | 188 颗 / 整帧 8.6 ms = 主线程 6.6 + 编辑器约 2.0；渲染线程 2.3、GPU 0.8 ms；最长 17.1 ms |

新测法里低档 GPU 只有高档的一半不到，画质档在 GPU 上生效；整帧差不多是因为两档的主线程都在 6.5–7.5 ms。

### 5.3 按图层的剔除距离（代替远景 impostor）

用户 2026-10-25 规定所有模型不减面、只发布一级 `_LOD0`，所以「远景换 impostor / 低模」这条路不走，也不做任何模型 LOD。远景地标本来就是剪影替身
（`LevelKit.BackdropImpostor`：不受光、不投影、无碰撞），面数大头在中近景的城墙、挡墙、平台块（第 7 节），不在远景。远处的负担改成按距离不画小东西：

- `CullLayers`（运行时）：关卡场景加载时，把 Default 层的静态 `MeshRenderer` 按包围盒最长边分到两个图层——小件 `Detail`（图层 8，≤ 1.6 m：碎石、罐子、灯笼、小摆件）和散布 `Scatter`（图层 9，≤ 6 m：巨砾、灌丛、矮树、货堆、掩体石）。
  蒙皮、粒子、线、地形、水 / 角色 / 第一人称层、带刚体 / 动画 / 可受伤 / 可交互组件的都不动；大件（建筑、崖壁、地标、远景剪影）永远不剔。
- 主相机按画质档设 `layerCullDistances`（球面距离，转头不会忽隐忽现）：

| 档 | 小件 | 散布 |
|---|---|---|
| 高 | 120 m | 雾终点 × 1.0（被雾完全吞掉之后才剔；各关雾终点 170–420 m） |
| 中 | 90 m | 雾终点 × 0.85 |
| 低 | 60 m | 雾终点 × 0.65 |

  雾没开时散布层用 400 m 兜底。沙暴把雾拉近时距离跟着收。
- 这两层和 Default 一样参与碰撞、子弹、视线、地面检测（`Layers` 的遮罩都是「除了某几层」），玩法不受影响。

### 5.4 地形

地形用 Unity Terrain 自带的分块 LOD，按画质档设（`QualityProfile` → `QualitySettings.terrain*` 覆盖）：

| 档 | 像素误差 | 细节（草、碎石）距离 | 细节密度 | 基础图距离 | 树距离 |

| 低 | 6 | 90 m | 0.5 | 2000 m | — |

地形本身按 `TerrainSpec.tiles` 分块（I1），相邻块设了邻接关系，Unity 按 pixelError 逐块选细分级别——这就是地形的分块 LOD，画质档只调像素误差。
基础图距离故意不动：关卡的风格化地形着色器没有基础图（basemap）那一路，拉近就会在远处换成没有分层的基础图。树都是摆的 Prefab（巨砾、松、柽柳），不用地形树，所以没有树距离可设，远处由 5.3 的散布层剔除。

### 5.5 SRP Batcher 与静态合批

SRP Batcher 开着；自写的着色器（`SF_StylizedLit` 等）每个 Pass 共用同一个 `UnityPerMaterial`，兼容 SRP Batcher。基线里绝大多数绘制走 SRP Batcher 路径
（见 JSON 里的 `srpDraws` / `standardDraws`）。关卡里摆的件标了静态，编辑器 Play 和打包都会做静态合批；SRP Batcher 下静态合批主要省的是变换上传，两者不冲突，保持默认。

### 5.6 第一人称渲染：枪模不再是叠加相机（第二批 E 路，2026-11-01）

**以前**：主相机（70°）上叠一台枪模相机（60°、近裁 0.01、只渲染 FirstPerson 层，`PlayerFactory.CreateCamera`）。每帧多一整台 URP 相机：剔除、Forward+ 灯光、RenderGraph 录制 / 编译 / 执行，
再加它自己的 SSAO（为枪模单独做深度法线预通道）、屏幕空间贴花、深度图、后处理。`perf-fp` 量到枪模相机自己 0.7–1.07 ms，整条相机栈去掉它少 1.1–1.5 ms。

**顺带查出的老问题：世界被后处理了两遍**。叠加相机开着 renderPostProcessing。URP 17 的相机栈里每台开了后处理的相机各跑一遍：
主相机给世界跑一遍，枪模相机把「已经后处理过的世界 + 枪模」再跑一遍（Neutral 色调映射、调色、白平衡、暗角、Bloom 都叠两次），枪模只走一遍。
从 601d1c16 起一直这样，审过的第一人称截图都是两遍的观感。perf 测量相机、第三人称图集机位、主菜单只走一遍，所以审过的画面里其实混着两种观感。
叠加相机一关后处理，世界上半屏平均亮度就 +11（3-1）到 +19（1-1）/ 255，天更浅、饱和和对比更低。
